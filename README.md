# Servizon — אופק שירות

**כלי הדמיה ותמיכה בקבלת החלטות למרכזי שירות.**

לכל מוקד שירות כבר יש Dashboard שמראה **מה קורה עכשיו**. מה שחסר הוא שכבת
החלטה: מנהל שרוצה לדעת *"מה יקרה אם נעלה אימוץ דיגיטלי מ-45% ל-60%?"* נאלץ היום
להעריך באוויר, ליישם בשטח, ורק אז לגלות את ההשפעה.

Servizon מוסיף שכבת סימולציה מעל הנתונים הקיימים. המשתמש מזיז מנופים תפעוליים
ורואה מיד כיצד כל KPI מגיב — מול המצב הנוכחי, עם כיוון, אחוז ומגמה.

**נתוני המקור לעולם אינם משתנים.** כל סימולציה רצה על Snapshot קפוא בזיכרון.

---

## מה מייחד את הכלי

**מודל אמיתי, לא מכפילים.** בליבה יושב **Erlang C** — מודל התורים התקני של
מרכזי שירות. לכן כל מספר שהמערכת מציגה ניתן להגנה מקצועית, והיא משחזרת את
ההתנהגות הלא-לינארית האמיתית: תוספת שני נציגים למוקד חנוק שווה הרבה, ואותה
תוספת למוקד רגוע כמעט ולא נמדדת.

**רענון לא הורס עבודה.** הנתונים החיים והתרחיש הם שני מקורות נפרדים לחלוטין.
כשרענון רקע מביא נתונים חדשים, מנופים שלא נגעת בהם עוקבים אחרי המציאות ומנופים
שכן נגעת בהם נשארים בדיוק במקומם.

**החלפת מקור נתונים = שורת קונפיגורציה.** מימושי CSV ו-SQL קיימים שניהם, ובדיקה
מריצה את אותו ETL ואותו מנוע על שניהם ומוודאת תוצאה זהה בייט-לבייט.

## המסכים

**מסך ראשי** — כל מוקדי השירות, עם חיפוש וארבעה מסננים (סוג · מחוז · סטטוס ·
גודל). הרשימה מווירטואלת, כי היעד הוא עשרות עד מאות מוקדים.

**מרכז הסימולציה** — שני טאבים, ערוצים דיגיטליים ומוקד טלפוני. שלושה טורים:
מנופים · מדדים · גרפים.

- **מנופים** — סליידר, קלט מספרי, איפוס, tooltip וגבולות מהשרת. מתחת לכל
  סליידר צבעוני יש פס אפור שמראה איפה המוקד נמצא **היום**. ההבדל בין "60%"
  לבין "60%, לעומת 45%" הוא ההבדל בין מספר להחלטה.
- **מדדים** — מצב נוכחי · תרחיש · הפרש · אחוז · חץ מגמה, עם הנפשת מספרים.
- **גרפים** — מד SLA, מגמת נפח, תרומת המנופים, השוואת עמודות, פרופיל שירות.
- **המלצות** — משפטים בעברית שנבנים מהמספרים שהמודל באמת הפיק.

**השוואת תרחישים** — עד שלושה תרחישים שמורים זה לצד זה, כולם מחושבים מול אותו
בסיס נתונים בבקשה אחת.

ההמלצות לכרטיסים.

## רשת סגורה

אחד, פורט אחד.

```bash
python scripts/build_offline_bundle.py
```

## סטטוס הנתונים

הרפוזיטורי כולל נתונים **סינתטיים** ל-20 מוקדים — עם עונתיות יומית ושבועית,
שעות שיא, ופריסה מכוונת של מוקדים תקינים, עמוסים וקריטיים. הם נועדו לפיתוח
ולהדגמה בלבד.

לפני שימוש בהחלטות אמיתיות יש לחבר את מקור הנתונים האמיתי
([`DATA-CONTRACT.md`](docs/DATA-CONTRACT.md)) **ולכייל את המקדמים** ב-
`backend/config/coefficients.yaml` מול היסטוריה. ערכי ברירת המחדל סבירים אך
אינם מכוילים מול נתוני צה"ל.
