# חוזה הנתונים

מסמך זה מגדיר את הטבלאות ש-Servizon קורא. כל מימוש Repository מייצר מסגרות
נתונים התואמות בדיוק לסכמות האלה, ולכן ה-ETL והמנוע אינם יודעים מהיכן הגיעו
הנתונים.

**המערכת קוראת בלבד.** אין נתיב כתיבה חזרה למקור.

## הערה על מספר הטבלאות

האפיון מתאר **שלוש טבלאות עובדה**: `interactions`, `staffing`, `channels`.
`centers` היא טבלת ממד קטנה הנושאת שמות וסיווגים. אם במערכת הייצור התכונות
האלה מוטמעות בתוך אחת משלוש העובדות — יש למפות אותן בשלב ה-ETL; שום דבר במורד
הזרם לא משתנה.

---

## `centers` — ממד

שורה אחת לכל מוקד.

| עמודה | טיפוס | תיאור |
|---|---|---|
| `center_id` | string | מזהה ייחודי. מפתח זר בכל שאר הטבלאות |
| `center_name` | string | שם תצוגה בעברית |
| `center_type` | string | `technical_support` · `personnel` · `logistics` · `medical` · `general_inquiries` |
| `district` | string | `north` · `center` · `south` · `jerusalem` · `hq` |
| `status` | string | דגל המקור. רק `offline` נלקח כפשוטו — ראה הערה למטה |
| `headcount` | int | מצבת כוללת |
| `working_hours_per_day` | float | שעות פעילות ביממה. `24` = 24/7 |

**סטטוס תפעולי נגזר, לא נקרא.** ה-ETL מסווג מוקד כתקין / בעומס / קריטי לפי
ה-SLA והנטישה החיים שלו. רק השבתה מוחלטת נלקחת מהעמודה. כך הרשת משקפת את
המציאות ולא שדה שמישהו עדכן לאחרונה לפני חודשים.

---

## `interactions` — עובדה

נפח פניות מצרפי לפי מוקד / ערוץ / מקטע חצי-שעתי.

| עמודה | טיפוס | תיאור |
|---|---|---|
| `center_id` | string | |
| `ts_bucket` | datetime | תחילת המקטע |
| `channel` | string | `phone` · `web` · `whatsapp` · `email` · `forms` · `chat` |
| `offered` | float | פניות שהגיעו |
| `handled` | float | פניות שטופלו |
| `abandoned` | float | פניות שננטשו לפני מענה |
| `aht_sec` | float | זמן טיפול ממוצע במקטע, שניות |
| `wait_sec` | float | זמן המתנה ממוצע, שניות |
| `resolved_first_contact` | float | פניות שנסגרו במגע הראשון |

`offered` הוא הבסיס לכל חישובי הנפח. הוא **כבר כולל** את הפניות החוזרות של
היום — ראה `SIMULATION-MODEL.md` §2.2 לסיבה שזה קריטי.

## `staffing` — עובדה

מצבת ואיוש לפי מוקד / מקטע.

| עמודה | טיפוס | תיאור |
|---|---|---|
| `center_id` | string | |
| `ts_bucket` | datetime | תואם ל-`interactions` |
| `agents_scheduled` | float | נציגים מתוקננים במשמרת |
| `agents_logged_in` | float | נציגים מחוברים בפועל |
| `shrinkage_pct` | float | אחוז זמן שאינו זמין למענה (0–100) |
| `sla_target_sec` | float | יעד המענה של המוקד |

## `channels` — עובדה

תצורת ערוצים. שורה אחת לכל מוקד / ערוץ.

| עמודה | טיפוס | תיאור |
|---|---|---|
| `center_id` | string | |
| `channel` | string | |
| `enabled` | bool | האם הערוץ פעיל במוקד |
| `self_service_rate` | float | 0–1. שיעור הפניות שנסגרות ללא נציג |
| `automation_level` | float | 0–1 |
| `agent_ai_usage` | float | 0–1 |
| `customer_ai_usage` | float | 0–1 |
| `knowledge_base_quality` | float | 0–1 |

ערכי התצורה מחושבים ל**ממוצע משוקלל בנפח** בשלב ה-ETL. ערוץ אוטומטי לחלוטין
שמטפל ב-2% מהפניות לא אמור להיקרא כאילו כל המוקד אוטומטי.

## אכיפת החוזה

`backend/app/repositories/schema.py` הוא מקור האמת. `_coerce` מאמת נוכחות של כל
עמודה וממיר לטיפוס המוצהר **בגבול המערכת**. עמודה חסרה נכשלת ברעש — עמודת NaN
שקטה הייתה מתגלה הרבה מאוחר יותר כ-KPI חסר היגיון.

---

## מה ה-ETL גוזר

ערכים שהמודל צריך ושהטבלאות אינן נושאות ישירות:

| נגזר | כיצד |
|---|---|
| `peak_hour_contacts` | ממוצע על פני הימים של שעת השיא של כל יום |
| `agents_scheduled` | המצבת **באותן שעות שיא בדיוק** |
| `patience_sec` | היפוך נוסחת הנטישה מול הנטישה וההמתנה שנצפו |
| `queue_size` | חוק ליטל על ההמתנה שנצפתה |
| `digital_adoption` | חלק הפניות שהגיעו בערוץ שאינו טלפון |
| `abandonment_target` | קבוע מדיניות (5%) — הטבלאות אינן נושאות יעד |

**יישור שעות השיא הכרחי.** מדידת נפח כממוצע על כל הימים מול מצבת שנדגמה רק
מהימים העמוסים משווה ביקוש של יום ממוצע מול איוש של יום שיא, ומחמיאה לכל מוקד
ב-10%–20%. זה היה באג אמיתי שהפך מוקדים בעומס לתקינים.

## מעבר למקור אמיתי

1. לממש את `ServiceDataRepository` מול המקור, או להשתמש ב-`SqlRepository`
   הקיים עם `SERVIZON_DATABASE_URL`.
2. אם שמות העמודות שונים — למפות אותם במימוש. שאר המערכת אינה משתנה.
3. להריץ את `tests/test_repositories.py` מול המקור החדש. הוא מוודא שה-ETL
   והמנוע מפיקים תוצאה זהה לזו של ה-CSV.
4. `SERVIZON_DATA_SOURCE=sql`.
